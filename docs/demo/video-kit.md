# 1024 演示视频素材包

面向「录一段可上传 / 可投屏的演示视频」，不是现场五分钟口播的替身。现场口播仍以 [`talk-track.md`](talk-track.md) 为准；本文件把**故事线、镜头表、口播、叠字、录制清单、现成素材路径**收成一份可执行的制作单。

两个版本：**6 分钟完整版**（§3–§5，七个场景全讲）和 **2 分钟短版**（§6，只讲一个 0，1024 上传用）。§7 起的字卡、素材、检查单、剪辑建议两版共用。

配套操作手册：[`../demo-script.md`](../demo-script.md)。全部离线跑 `fixtures/pick-order-details`，不连生产、不执行 SQL。

---

## 1. 一句话定位

> 页面上只是一个 `0`。MES X-Ray 把这一个数字背后的 Web → API → Service → 存储过程 → UDF → 表列全部扫成证据图；运行时取值叠上去；AI 只能引用证据说话，说不出来就标「需要更多证据」。

**受众**：1024 程序员节观众（工程师为主，可能含产品 / 架构）。  
**不要讲**：安装步骤、.NET 版本、CI、P2 多拣货单。  
**一定要留下的印象**：证据图不是手画的；AI 会停下来；缺口是公开的。

## 5. 完整口播（可直接念）

下面是 [`talk-track.md`](talk-track.md) 的「录制版」：去掉了现场手势说明，保留可朗读的句子。时间码对应 §4。

### 0:10 幕 1 — 只是一个 0

> 拣货单详情页上，T12288 这一行的 Available Quantity 显示 0。就一个 0。  
> 这张图是这个 0 背后的全部链路：Web VP 页面、EBBA API、Controller、Service、Query，四个存储过程和一个函数，下面是表、CTE 和系统参数。一共 210 个节点、363 条边，都是扫描器从代码和 SQL 里读出来的，不是手画的。  
> 今天要回答的问题只有一个：这个 0 是怎么来的，我们能不能证明它。

### 0:40 幕 2 — 溯源

> 一次点击。上面的执行路径是静态调用链：页面、API、Service、Query、存储过程 `AP_Pick_GetPickOrderRows`，最后到函数 `AF_Pick_GetAvailableQuantity`。  
> 下面是上游血缘：JSON 字段、属性、结果列、中间列的求和，再往上是一个 CASE。CASE 按 `@WMS_Enabled` 分两支：关 WMS 走本地估算，开 WMS 走这个 UDF。  
> 血缘没有在函数调用处停下。函数的脱敏定义已经在 fixture 里，扫描器沿 RETURN 继续追，进到 CTE，最后落到 `INVENTORY2` 的库存列。

（展开时补一句）  
> 函数内部默认折叠在节点上，点一下展开，相机钻进 RETURN 和基表列——图始终可读。

### 1:35 实时追踪

> 现在把一次真实调用、脱敏后的 fixture，叠到图上。  
> T12288：拣货 18，在手 0，已分配 18，可用 0；`WMS_Enabled` 是 1。  
> 拣货、在手、已分配三个数最后都落在表列上；Available 不一样——它是同一个存储过程里的 CASE，开了 WMS 就走 UDF。所以它是 0 而别的不是，这不是巧合，是来源不同。

### 2:15 调查（主戏，念慢一点）

> 让调查器解释这个 0。结论是「需要更多证据」，置信度 80%。  
> 先看可审计步骤：定位节点、叠加 trace、重建路径、遍历血缘、按 `WMS_Enabled = 1` 评估分支、检查定义。这是它做了什么，不是它怎么想的。  
> 每条事实后面都挂着证据芯片；点芯片，图会跳过去。  
> 关键事实：本次走的是 WMS 分支；函数里要么返回常量 1000，要么返回 `ISNULL(SUM(…), 0)`；走哪一支取决于交付方式表的行数据，这次 trace 没有捕获那些行。  
> 然后是唯一一条假设，状态「未验证」：这个 0 很可能是 ISNULL 的回退值，也就是没有匹配的库存行。附带一个只读的下一步：去 TEST 查那几张表。  
> 注意区分：同一个字段点「解释」，静态血缘完整，结论是「已知」；点「调查」问为什么是 0，答案依赖假设，所以是「需要更多证据」。证据说到哪里，结论就到哪里。

### 3:50 影响

> 反过来问：如果有人切 `WMS_Enabled`，会影响什么？  
> 一条沿调用链走到页面，一条沿数据流走到 `availableQuantity`。这是切参数之前该看的图。

### 4:25 复杂字段 + 缺口

> 换一个复杂字段：库位是 `STRING_AGG` 按 FIFO 拼起来的，实时取值一路挂在链上，每一跳都是已知。  
> （可选）对照目的车库位：链停在 `AP_Pick_GetPutStorageBin`。代码里过程名不是常量，是站点配置；图上边的证据类型是 `configuration`。过程定义还没拿到，X-Ray 就停在这里，不猜。

### 5:20 收尾

> 回到全图。X-Ray 不是一个聊天框。扫描器把代码和 SQL 变成证据图，运行时把取值绑上去，AI 只允许基于证据说话。  
> 状态栏一直写着边界：只读、白名单工具、不执行 SQL、不改参数和数据。  
> 第一个闭环已经走通：UDF 定义到位之后，availableQuantity 从「需要更多证据」变成「已知」，多出来的节点没有一条是手画的。下一步同样具体：目的车那个存储过程的定义。

## 6. 2 分钟短版（约 520 字 · 1.3–1.5 倍语速）

§3–§5 是完整版。这一节是**可上传的 2:00 成片**，只讲一个故事：页面上只是一个 `0` → 扫成证据图 → 叠上真实取值 → AI 说到证据为止。不上影响分析、库位字段、目的车缺口、中英切换。

两条制作路线，故事、口播、时间轴相同：

- **路线 A · 录屏**：§6.5 的素材表。「流转」由产品自己演——图标题栏的 **▶ 回放流转**（深链 `&replay=1` 自动播、`&replay=hold` 只变暗等待）把一次追踪播成约 10 秒的动画：路径先暗下去，调用沿执行路径逐节点向下、每条边跑一个光点，取值再沿血缘逐层向上，最后落进字段亮出 `T12288: 0`。
- **路线 B · 全片交给 MiniMax H3 生成，不录屏**：[`h3-brief.md`](h3-brief.md) 把这 2 分钟切成 12 段（每段 ≤ 15 秒）的提示词，真实截图只当构图 / 配色参考，四张字卡（`cards/*.png`）当首帧，旁白按段切好。拿到另一台电脑上直接生成、按序拼接即可。

观众离开时只需要带走三句话：

1. 页面上只是一个 0。
2. X-Ray 把这个 0 扫成证据图，再叠上真实取值。
3. AI 只能引用证据；说不清就停，标「需要更多证据」。

三条硬规则：

1. **标识符不念。** `AP_Pick_GetPickOrderRows`、`AF_Pick_GetAvailableQuantity`、`ISNULL(…)` 只在画面上出现（节点本身就是标签，需要时后期放大到节点），口播说「存储过程 / 函数 / 回退值」。
2. **一镜一动作**，做完停 1.5 秒。「解释 vs 调查」的对照用后期并排卡，不在镜头里切页。
3. **旁白先录、画面后剪。** 约 520 字压在 112 秒口播窗口里 ≈ 4.6 字/秒：1.3 倍够用，1.5 倍是上限。后期加速真人录音会变音——要么用 TTS，要么录音时本来就念快。

## 9. 录制检查单（开机前）

1. `npm run e2e` 前一天全绿。  
2. `XRAY_LANG=zh scripts/xray.sh demo`，`status` 双方 healthy；记下**实际** web 端口。  
3. 打开场景 4 深链：必须看到「需要更多证据」、约 80%、有假设。这一条通了 = API / 图 / fixture / 调查器全在线。  
4. 浏览器 100% 缩放，窗口 ≥ 1400，关通知，关多余标签。  
5. 决定是否录系统音；口播用外接麦，环境噪声小。  
6. 深链提前粘进备忘录 / 浏览器书签栏，点错就贴链接，不要现场找回路。  
7. 出错恢复：`scripts/xray.sh restart --api-only --no-build`；错订单 → 改回 `PICK0843858`。  
8. **不要**在录制中途 `stop` 其它占端口的项目；脚本会自己换端口。  
9. 本机若有很久以前的 `dotnet run` 残留，成片前用 `scripts/xray.sh restart` 起一份**当前**图（站点配置解析 PutStorageBin 那一版）。

## 10. 剪辑建议（务实版）

- **工具**：QuickTime / OBS 录屏 + 任意剪辑（剪映 / CapCut / Premiere 皆可）。  
- **光标**：开系统「摇晃时放大指针」或 OBS 高亮，观众才能跟上点的是哪。  
- **停顿**：每个场景定格 1–2 秒再开讲；展开函数、点证据芯片这两处各留 1 秒动画播完。  
- **B-roll**：不需要实拍产线；不够切就用静帧慢推（Ken Burns）顶口播。  
- **字幕**：口播中文硬字幕建议；专有名词保留英文（`WMS_Enabled`、`AP_Pick_GetPickOrderRows`）。  
- **BGM**：可无；若有，压到 -24 dB 以下，口播段落再降。  
- **不要剪掉**：场景 4「解释 vs 调查」那句对比——这是产品立场，不是过渡句。

## 11. 问答卡（片尾或评论区置顶）

| 问题 | 十秒答法 |
|---|---|
| 这是 LLM 吗？ | 演示默认离线规则引擎；接模型时同一套证据绑定校验，乱引用会降级。 |
| 会改数据吗？ | 不会。只读白名单，无 UPDATE / 任意 SQL / 自动修复。 |
| 图是手画的吗？ | 不是。Roslyn + ScriptDom 扫描；缺口在状态栏公开。 |
| 为什么调查不是「已知」？ | 静态链完整 ≠ 解释了这个 0；0 依赖未捕获的行数据，所以标假设。 |
| 下一步？ | `AP_Pick_GetPutStorageBin` 的脱敏定义进 fixture，这条链也能变已知。 |
