# MiniMax H3 提示词包（2 分钟短版 · 全片生成）

配套 [`video-kit.md`](video-kit.md) §6。这份文件是给**另一台电脑上的 MiniMax H3** 用的：不录屏，整条 1:56 的片子由 H3 分 12 段生成，再按顺序拼起来。每段提示词都可以直接复制粘贴。

H3 的硬约束（官方文档 <https://platform.minimaxi.com/docs/guides/video-generation>）：

- 单段 **4–15 秒**（整数秒），768P 或 2K，24 fps，16:9，原生立体声
- 模式：文生视频（T2VA）、首帧（I2VA）、首尾帧（FL2VA）、**全能参考**（最多 9 张图 + 3 段视频（每段 ≤ 15 秒）+ 3 段音频，合计 ≤ 12 个文件）
- 提示词 ≤ 7000 字符；**每个上传文件都要在提示词里声明角色**（`@image1`、`@video1`、`@audio1`）
- 默认会切镜、会自己加东西：要单一镜头就明说，要它别加人物 / 指针 / 文字就明说

## 0. 设计原则：让生成结果像一款真实软件，而不是像一段 AI 视频

生成模型复现不了 210 个节点的名字，也不需要。观众记住的是**一个 0 被一层层解释**。所以：

1. **一套风格块贴在每段开头**（§2），配色、节点样式、运镜语言全片相同。
2. **一段锚定片**：C1 先生成、先验收，之后每段都把 C1 成片当 `@video1` 画风参考，节点长什么样以它为准。
3. **每段只允许 ≤ 5 个可读字符串**，我在提示词里逐字写出；其余界面文字一律写成「不可读的细小模糊占位」——这样生成物里不会出现读得出来的错字。
4. **必须逐字准确的画面用真实首帧**：片头、对照卡、收束卡、片尾从 `cards/*.png` 起播（I2VA），文字不由模型生成。
5. **参考图只借构图和配色**：`docs/demo/*.png` 是产品的真实截图，作为 `@image` 上传时只说「参考构图 / 配色 / 节点样式，不要照抄文字」。
6. **单一连续镜头、固定机位或极慢推近**、无人物、无鼠标指针、无水印、无镜头光斑。专业感来自克制。

## 3. 旁白的两种做法

- **方案 A（推荐）**：H3 各段只出画面和环境声，旁白用同一个 TTS 声音一次录完（1.3–1.5 倍），拼接时叠上去。声音全片一致，字句一定准确。
- **方案 B**：让 H3 直接念。每段上传同一段 `@audio1`（5–15 秒的旁白音色样本，可以是 TTS 出的第一句），提示词里声明「@audio1 是画外旁白的音色参考」，并保留下面每段的「画外旁白」行。风险：音色段间漂移、个别字念错、模型自作主张加字幕。

下面每段提示词的「画外旁白」行按方案 B 写；走方案 A 时**删掉这一行**，其余不变。

## 5. 验收（每段都过一遍，100% 尺寸逐帧看）

| 检查项 | 要求 |
|---|---|
| 可读文字 | 只有本段列出的字符串可读，且逐字正确；其余文字必须是模糊占位，**不能有读得出来的错字** |
| 首帧段（C0 / C9 / C10 / C11） | 文字与首帧图逐字、逐像素一致，不漂移、不重排 |
| 风格 | 配色在 §2 之内（青色不发紫、不发绿；琥珀色只出现在「需要更多证据」「假设」「未验证」）；节点样式与 C1 一致 |
| 镜头 | 单一连续镜头，无剪切；相机只有写明的推近 / 平移；无抖动、无光斑 |
| 禁止项 | 没有人物、手、鼠标指针、水印、字幕（方案 B 时尤其检查有没有自动加字幕） |
| 顺序 | C4 的点亮顺序必须是「先向下再向上、字段最后」；C2 路径自上而下 |
| 时长 / 规格 | 与表中一致；24 fps；16:9 |
| 声音（方案 B） | 旁白字句与提示词一致、音色与 C1 相同；没有多出来的对白 |

**重生成**：同一段最多 3 次（微调提示词或换参考图，不换模式）。C1 是例外：它是全片的样子，值得多试几次；C1 定了以后不要再改 §2 的风格块。

**留档**：每次生成记下 task_id、提示词版本、结论，成片用到的那一版提示词复制到工程目录。

## 6. 拼接与音频

1. 12 段按 C0 → C11 顺序**硬切**拼接（剪映 / CapCut / Premiere，或 ffmpeg concat 均可）。所有段的首尾都是静止画面，硬切不会跳。
2. **方案 A**：先把 12 段拼成静音（或只留环境声 -30 dB）的 1:56，再叠上一次录完的 TTS 旁白（每段的旁白起点对齐该段的 0.8–1.0 秒）。**方案 B**：段与段之间旁白自然衔接，只需检查音量一致。
3. 叠字只有一处（C5 的「两个 0，两条路」）已由 H3 生成；不要再加别的字幕，除非旁白用了 1.5 倍以上语速——那就加硬字幕，单行 ≤ 16 字。
4. BGM 可无；有则 ≤ -24 dB，旁白时再压。
5. 先用 768P 迭代，全部验收通过后再用 2K 重新生成（或用官方的 2K 再生成接口），最后导出。

## 8. 走 API 时

Hailuo 网页版（<https://hailuoai.video/tools/minimax-h3>）可以直接选模式、拖入参考文件、粘贴提示词，最省事。走 API 时以官方文档为准（<https://platform.minimaxi.com/docs/api-reference/video-generation-v2-create.md>）：`POST /v2/video_generation`，`model` 为 `MiniMax-H3`，`content` 是文本 / 图片 / 视频 / 音频项组成的数组，`duration` 为 4–15 的整数，`resolution` 为 `768P` 或 `2K`，`ratio` 为 `16:9`；接口异步，返回 `task_id` 后轮询 `GET /v2/query/video_generation/{task_id}`。首帧、参考文件的具体字段名和角色标记按文档填写，不要凭记忆猜。
