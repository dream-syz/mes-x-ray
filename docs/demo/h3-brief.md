# MiniMax H3 生成包（2 分钟短版 · 全片生成 · 不录屏）

配套 [`video-kit.md`](video-kit.md) §6。整条 2:00 由 H3 分 **14 段**生成，再按顺序硬切拼接。所有材料都在 [`h3/`](h3/) 目录，拷到生成用的那台电脑上就能开工：

| 文件 | 作用 |
|---|---|
| [`h3/manifest.json`](h3/manifest.json) | 14 段的顺序、时长、首尾帧、提示词文件 —— 唯一的时间轴来源 |
| [`h3/prompts/C00.txt … C13.txt`](h3/prompts/) | 每段一份完整提示词，直接整文件复制粘贴，不需要再拼接任何东西 |
| [`h3/frames/f01.png … f11.png`](h3/frames/) | 11 张 1920×1080 的首尾帧（下面解释为什么是它们而不是真实截图） |
| [`cards/*.png`](cards/) | 片头、对照卡、收束卡、片尾四张字卡，作为 C00 / C11 / C12 / C13 的首帧 |
| [`h3/h3.py`](h3/h3.py) | 可选：按 manifest 批量提交 API、轮询、下载、生成拼接清单；也能导出旁白 SRT |
| [`h3/narration.srt`](h3/narration.srt) / [`h3/narration.txt`](h3/narration.txt) | 旁白：带时间码的 29 条字幕 / 按段切好的台词 |
| [`h3/frames.html`](h3/frames.html) + [`h3/render.sh`](h3/render.sh) | 首尾帧的源文件；改文案或布局后重新渲染 |

H3 的硬约束（官方文档 <https://platform.minimaxi.com/docs/guides/video-generation>，2026-10-01 核对）：单段 4–15 秒整数；768P 或 2K；首帧 / 尾帧 ≤ 1 张各；**首尾帧模式与全能参考模式互斥**（有了首尾帧就不能再传参考图、参考视频、参考音频）；提示词 ≤ 7000 字符；接口异步。

---

## 1. 思路：让模型只做「两张图之间的运动」

生成模型画不准 210 个节点的名字，也记不住上一段的样子。所以这套方案把**所有静态的东西**从模型手里拿走：

1. **每一段都是首尾帧模式。** 首帧和尾帧是我们自己渲染的 1920×1080 PNG（`frames.html` 的 11 个状态），文字、配色、布局、节点位置在两端被钉死，模型只负责中间 4–15 秒的运动。
2. **段与段共用同一张帧。** C02 的尾帧就是 C03 的首帧，C03 的尾帧就是 C04 的首帧……拼接时的硬切落在两张像素相同的画面上，观众看不到接缝，也不需要任何转场。
3. **帧是真实 UI 的简化版，不是截图。** 同一套配色、同样的三栏布局和状态栏，但图只有 28 个节点，每个节点一行可读的类型（页面 / API / 服务 / 存储过程 / 函数 / 表 / 字段 / 属性 / 结果列 / 求和 / CASE / 参数），名字除了几个主角（`availableQuantity`、`WMS_Enabled`、`CASE`、`RETURN`、`CTE`、`INVENTORY2`、`onHandQuantity`）全部画成灰色横条。给不了模型小字，它就写不出错字。
4. **必须逐字准确的画面从字卡起播。** 片头、对照卡、收束卡、片尾只有首帧（I2VA），画面只做呼吸和极慢推近。
5. **提示词只写运动的顺序和时间。** 每段开头是同一个风格块（无剪切、无人物、无指针、不新增文字、横条保持横条、最后 0.5 秒与尾帧一致），然后是「首帧是什么、尾帧是什么、区别只有哪些」，再按秒写出节点点亮的顺序。顺序本身就是叙事：调用向下、取值向上、字段最后。

真实截图（`01-architecture.png` 等）不再上传给模型——首尾帧模式不接受参考图，而且它们的小字只会被画坏。它们留给人看。

## 3. 旁白的两种做法

- **方案 A（推荐）**：H3 各段只出画面和环境声。旁白用同一个 TTS 声音、按 [`h3/narration.txt`](h3/narration.txt) 一次录完，拼接后按 [`h3/narration.srt`](h3/narration.srt) 的时间码对齐叠上去（SRT 也可以直接烧成字幕）。声音全片一致，字句一定准确。`h3.py submit` 默认就是这个方案：提交前会把提示词里的「画外旁白」段删掉。
- **方案 B**：让 H3 直接念（`h3.py submit --voice`，或在网页里粘贴完整提示词）。每段提示词里都写了「中性、沉稳、语速稍快的中文女声，无画面内说话者，不生成字幕」。风险：音色段间漂移、个别字念错、模型自作主张加字幕——首尾帧模式不能传音色参考，这个漂移没有办法用参考音频压住。

## 4. 怎么生成

### 网页版（<https://hailuoai.video/tools/minimax-h3>）

每段三步：选「首尾帧」（C00 / C11 / C12 / C13 只传首帧）→ 上传 manifest 里写的两张图 → 整文件粘贴 `prompts/Cxx.txt`，时长按 manifest 填，分辨率先 768P。不要开任何「提示词扩写 / 智能优化」：这些提示词是故意写死的，扩写只会往里加东西。

### API（`h3.py`，只依赖 Python 3 标准库）

```bash
export MINIMAX_API_KEY=…            # 只放在生成用的电脑上，不进仓库
cd docs/demo/h3
python3 h3.py plan                  # 看时间轴
python3 h3.py submit --dry-run      # 看每段会发什么（图片以 base64 内联，单请求 100–300 KB）
python3 h3.py submit --only C00,C11,C12,C13     # 先出四张字卡段
python3 h3.py poll --download       # 轮询并下载到 out/Cxx.mp4
python3 h3.py submit --only C01     # 再磕 C01，然后 C02…C10
python3 h3.py submit --resolution 2K            # 全部验收通过后出 2K
python3 h3.py concat                # 写 out/concat.txt 并打印 ffmpeg 命令
```

国际站把 `MINIMAX_API_BASE` 指到对应域名即可。请求字段按官方 OpenAPI：`content[]` 里 `text` + `image_url`（`role` 为 `first_frame` / `last_frame`），`resolution`，整数 `duration`；首尾帧模式下宽高比由图片决定（1920×1080 → 16:9），不传 `ratio`。

### 生成顺序

1. 四张字卡段（C00 / C11 / C12 / C13）——最稳，顺便确认账号、分辨率、水印设置。
2. **C01**：第一段真正的图。它通过了，说明模型能在这套帧之间稳住文字和横条；它不行，先调它，不要往下走。
3. C05 → C06（流转的核心两段），再 C02 → C04，再 C07 → C10。
4. 全部 768P 验收通过后，用 `--resolution 2K` 重出（或走官方的 2K 再生成接口）。

## 5. 验收（每段都过，100% 尺寸逐帧看）

| 检查项 | 要求 |
|---|---|
| 首尾两端 | 前 0.5 秒与首帧、后 0.5 秒与尾帧逐像素一致：位置不漂、文字不重排、横条还是横条 |
| 可读文字 | 只有两张帧上有的文字出现；字形逐字正确；**不能有横条变成的伪文字** |
| 顺序 | C05 自上而下 8 个节点、C06 自下而上、字段最后；C02 两列同向下；C03 先展开后推近到位 |
| 运动 | 没有写明的推近 / 拉远不出现；无剪切、无抖动、无转场、无光斑 |
| 禁止项 | 无人物、手、鼠标指针、水印、字幕（方案 B 尤其查字幕） |
| 色彩 | 青色不发紫、不发绿；琥珀色只在「需要更多证据」「假设」「未验证」 |
| 规格 | 时长与 manifest 一致；24 fps；16:9 |

**重生成**：同一段最多 3 次。换提示词只改时间线那几行，不改风格块；帧不对就改 `frames.html` 重新渲染（`XRAY_PW_CHANNEL=chrome docs/demo/h3/render.sh f06 f07`），改完的帧会同时改掉相邻两段的首尾，要一起重出。

**留档**：`out/tasks.json` 记录每段的 task_id、分辨率、是否带旁白、状态和成片地址。

---

## 6. 拼接

1. `python3 h3.py concat` 写出 `out/concat.txt`，按 C00 → C13 顺序硬切。相邻段共用同一张帧，不需要任何转场；字卡段前后的切换本来就是字卡插入。
2. 方案 A：先拼成静音（或环境声 -30 dB）的 2:00，再叠一次录完的 TTS 旁白；`narration.srt` 的时间码就是每句的起点，每段旁白从该段 0.6 秒开始。
3. 叠字只有一处（C07 的「两个 0，两条路」）已经在帧里；不再加别的字幕，除非旁白超过 1.5 倍语速——那就把 `narration.srt` 烧进去，单行 ≤ 16 字。
4. BGM 可无；有则 ≤ -24 dB，旁白时再压。

---

## 7. 改帧

`frames.html?state=fNN` 是一个页面十一个状态；节点、连线、每个状态点亮哪些、显示哪些胶囊都在文件顶部的 `NODES` / `EDGES` / `STATES` 里。改完跑 `render.sh`，再跑 `h3.py submit --dry-run` 看看哪些段受影响。字卡在 `cards/*.html`，渲染命令写在各文件头部。

所有帧和字卡只含离线 fixture 里的数字与名字，不含真实主机名、工号或未脱敏数据。
